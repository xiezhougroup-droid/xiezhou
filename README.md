# 采购询价本地工作流

这是一个可重复运行的本地脚本工作流原型。

## 当前能做什么

1. 读取正式询价清单底表；
2. 按指定供应商包筛选正式报价项；
3. 输出指定供应商包的报价邀请包 Word 文档；
4. 扫描 `图纸/` 文件夹，生成图纸资料索引；
5. 根据配置规则匹配图纸附件；
6. 输出人工确认项；
7. 生成采购包智能拆分总表；
8. 不覆盖原始文件，所有结果进入 `output/` 的时间戳目录。

## 默认样例

默认包：

`百叶风口及防雨百叶采购报价包`

来源供应商包字段：

`铝合金门窗供应商包`

## 如何运行

### 推荐：打开网页助手

如果要让同事在同一局域网访问，负责人电脑启动：

```text
启动局域网网页助手.command
```

启动窗口会显示 `http://你的电脑IP:8876`，把这个地址发给同事。

Windows 双击：

```text
启动网页助手-Windows.bat
```

Mac 双击：

```text
启动网页助手.command
```

浏览器会打开：

```text
http://127.0.0.1:8876
```

在网页上上传文件、点击按钮、下载结果。

### 命令行一键跑完整闭环

```bash
./采购询价本地工作流/run_full_loop.command
```

当前完整闭环包括：

1. 按昨日样板标准生成采购包拆分总表；
2. 批量生成全部采购包邀请清单；
3. 分析已回收供应商报价并输出谈判策略；
4. 根据采购员谈判反馈生成最终推荐结果。

### 生成采购包拆分总表

先跑这个，用来校准“哪些材料归哪个采购包、哪些需要人工确认”：

```bash
./采购询价本地工作流/run_package_split.command
```

输出文件：

```text
采购询价本地工作流/output/时间戳_采购包拆分总表/采购包智能拆分总表.xlsx
```

### 生成单个供应商包报价邀请包

在当前项目目录打开终端，运行：

```bash
./采购询价本地工作流/run_workflow.command
```

或：

```bash
/Users/houzhou/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 采购询价本地工作流/src/run_workflow.py
```

也可以临时指定输入文件，不改配置文件：

```bash
./采购询价本地工作流/run_workflow.command \
  --boq 正式询价清单底表-第二版.xlsx \
  --public-info 项目公共信息确认表.rtf \
  --drawings 图纸 \
  --package baiye_fengkou
```

运行后到：

```text
采购询价本地工作流/output/
```

查看新生成的时间戳目录。

## 输出内容

每次运行会输出：

- `图纸资料索引及附件匹配表.xlsx`
- `百叶风口及防雨百叶采购报价包.docx`
- `处理日志.txt`

## 供应商报价回收与分析

供应商报价文件放到：

```text
采购询价本地工作流/input/supplier_quotes/
```

建议按采购包建子文件夹，例如：

```text
supplier_quotes/电线电缆包/供应商A-报价清单.xlsx
```

然后运行：

```bash
./采购询价本地工作流/run_analyze_quotes.command
```

输出：

- `供应商报价分析及谈判策略.xlsx`

## 谈判后最终推荐

谈判反馈表位置：

```text
采购询价本地工作流/input/negotiation_feedback.xlsx
```

如果文件不存在，运行以下命令会自动创建模板：

```bash
./采购询价本地工作流/run_finalize_recommendation.command
```

采购员填写最终报价、付款条件、供货周期、技术/品牌确认情况、确认状态和推荐意见后，再运行同一命令，输出：

- `采购推荐合作结果.xlsx`

## 规则配置

主要配置文件：

- `config/workflow.json`
- `config/packages.json`
- `config/procurement_classification_rules.json`

后续新增供应商包时，优先在 `packages.json` 中新增配置，不要直接改代码。
采购包智能拆分规则优先维护 `procurement_classification_rules.json`。

## 给同事使用的建议

如果同事不懂命令行，可以让程序员后续把 `run_workflow.command` 包一层简单界面；当前版本已经可以先在本机双击或终端运行。每次运行都会生成新的时间戳目录，不会覆盖历史输出。

## 给程序员整理的建议

当前脚本是最小原型，后续可以整理成：

- 一个输入页：上传底表、项目公共信息表、选择图纸文件夹、选择供应商包；
- 一个规则维护页：维护供应商包名称、关键词、附件匹配规则、正文模板；
- 一个输出页：下载报价邀请包、图纸索引表、人工确认项；
- 一个报价回填流程：在下一阶段基于追溯号识别供应商报价并回填底表。

## 重要约束

- 不覆盖原始底表；
- 不覆盖原始图纸；
- 不修改输入文件；
- 报价清单必须保留追溯号；
- 不确定图纸进入候选或人工确认，不直接作为正式附件。
